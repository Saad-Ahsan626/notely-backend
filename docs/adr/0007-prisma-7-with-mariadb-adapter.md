# 0007. Use Prisma 7 with the MariaDB driver adapter

- **Status:** Accepted
- **Date:** 2026-09-15

## Context

ADR 0002 selected Prisma as the ORM. Prisma 7 changed how it connects to databases: the Rust query
engine was replaced by a TypeScript query compiler, and every SQL database is reached through a
**driver adapter** that wraps a regular JavaScript driver. Configuration for the CLI moved into
`prisma.config.ts`, and `.env` files are no longer loaded automatically.

While installing, three supply-chain issues surfaced:

1. The `prisma` CLI's npm `latest` tag pointed to a release candidate (`8.0.0-rc.15`), while
   `@prisma/client` was on stable `7.10.0`. CLI and client versions must match.
2. Prisma pins the `mariadb` driver (runtime) and `mysql2` (CLI only) to versions with published
   security advisories, including credential leaks.
3. `deepmerge-ts`, used only when the CLI merges its own configuration file, has an advisory whose
   fix is a new major version.

## Decision

- Use **Prisma 7.10.0** with the **`@prisma/adapter-mariadb`** adapter, which speaks the MySQL
  protocol.
- Pin `prisma`, `@prisma/client` and `@prisma/adapter-mariadb` to the **exact same version** (no `^`).
- Generate the client with the ESM `prisma-client` generator into `src/generated/prisma`
  (gitignored; regenerated by `postinstall` and after migrations).
- Load `.env` in `prisma.config.ts` with Node's built-in `process.loadEnvFile()` instead of adding
  `dotenv`.
- Use npm `overrides` to force patched transitive versions: `mariadb` 3.4.7 and `mysql2` 3.24.4.
  `mariadb` is also a direct dependency because the app imports its types.
- **Accept** the `deepmerge-ts` advisory for now: it only affects merging of our own, trusted
  configuration file, and forcing a major version could break the CLI. Revisit when Prisma
  updates it.
- Leave npm's blocked install scripts for `prisma`, `@prisma/engines`, `argon2` and `esbuild`
  unapproved: everything works without them (verified), so no extra code runs at install time.
- `PrismaService` verifies the database with a direct driver connection at startup, because the
  pool retries failed connections and reports only a generic timeout.

### Alternatives considered

- **Prisma 6** with the classic engine: stable, but a legacy architecture that Prisma 7 replaces.
- **Prisma 8 release candidate:** not production-ready.
- **TypeORM / Drizzle:** see ADR 0002; no reason to revisit.

## Consequences

- No platform-specific query engine binary; installs and CI are simpler.
- The generated client must be regenerated after schema changes (`npm run db:migrate` does it).
- Overrides must be reviewed on every Prisma upgrade and removed once Prisma ships patched
  dependencies.
- Driver options (pool size, timeouts, TLS) are configured in one place:
  `src/database/database-connection.ts`.
