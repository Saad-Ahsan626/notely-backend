# 0008. Use UUIDv7 primary keys

- **Status:** Accepted
- **Date:** 2026-09-15

## Context

Resource IDs appear in URLs (`/api/v1/notes/:id`). Sequential integers let anyone guess other IDs
(`/notes/5` → `/notes/6`), which makes enumeration attacks and data leaks easier.

Random UUIDs (version 4) fix guessability but hurt MySQL performance at scale: InnoDB stores rows in
primary-key order (a clustered index), so random keys are inserted all over the index. That causes
page splits, fragmentation and slower inserts as tables grow.

## Decision

Use **UUID version 7** for all primary keys, generated by Prisma with `@default(uuid(7))` and stored
as `CHAR(36)`.

UUIDv7 starts with a 48-bit Unix timestamp in milliseconds followed by random bits, so it is:

- **Unguessable**, like UUIDv4, thanks to its random part.
- **Time-ordered**, so new rows are appended near the end of the index, like auto-increment keys.

### Alternatives considered

| Option             | Guessable | Insert performance at scale | Decision                                   |
| ------------------ | --------- | --------------------------- | ------------------------------------------ |
| Auto-increment int | Yes       | Excellent                   | Rejected                                   |
| UUIDv4             | No        | Degrades (random inserts)   | Rejected                                   |
| **UUIDv7**         | No        | Good (ordered inserts)      | Chosen                                     |
| ULID               | No        | Good                        | Rejected: not a UUID, less tooling support |

`BINARY(16)` storage would be more compact than `CHAR(36)`, but makes IDs unreadable in SQL tools
and adds conversion code. `CHAR(36)` is the better trade-off at this project's scale.

## Consequences

- IDs reveal their approximate creation time. This is acceptable: notes already expose `createdAt`.
- IDs are generated by the application (Prisma), not by MySQL. Rows inserted with raw SQL must
  supply an ID.
- The API contract describes IDs as UUID strings; clients must not rely on a specific version.
